# ChadNext — Agent Guide

ChadNext is an **agent-native SaaS starter**: Next.js 16 + Convex + better-auth + Polar + AI SDK v7, whose demo product is an AI run-loop app with an in-app assistant ("Sigma"). This file is the single source of truth for AI coding agents (Claude Code, Cursor, Codex). Tool-specific files (`CLAUDE.md`, `.cursor/rules/`) point here — never edit them to diverge.

**The definitive plan** (scope, guardrails, phases): `docs/plans/2026-09-01-chadnext-v2-definitive-plan.md`. Read it before any feature work.

## Commands

```bash
pnpm dev          # dev server (Turbopack). Note: Serwist PWA is prod-only.
pnpm build        # production build — must pass before any commit
pnpm lint         # eslint
npx convex dev    # Convex backend — REQUIRES interactive login; ask the user to run it
```

## Stack invariants (violating these breaks the template)

- **Next.js 16**: `src/proxy.ts` (NOT middleware.ts). `params`/`searchParams`/`cookies()`/`headers()` are async — always `await`.
- **Tailwind 4**: CSS-first config in `src/app/globals.css`. No `tailwind.config.*` exists; never create one.
- **Convex is the only backend.** Data + business logic live in `convex/` with explicit validators and per-user ownership checks. Never add another database. Never call internal mutations without auth context.
- **Auth**: better-auth (GitHub OAuth + Email OTP) via `@convex-dev/better-auth`. All dashboard data is scoped by `ctx.userId`.
- **Billing**: Polar fixed tiers (Free/Pro) defined in `src/config/subscription.ts`. No usage-based/metered billing — ever.
- **AI**: AI SDK v7. Provider resolution: `src/config/ai.ts` (Next-side) and `convex/aiConfig.ts` (Convex-side), priority = Vercel AI Gateway → OpenAI → Anthropic → mock. `@convex-dev/agent` v0.7+ uses `instructions:` (not `system:`).
- **Client data layer**: TanStack Query via `@convex-dev/react-query` — use `convexQuery(api.x.y, args)` with `useQuery` from `@tanstack/react-query`. Native `convex/react` `useQuery` is allowed for quick internals but prefer the adapter for new pages.
- **Env**: all Next-side env access goes through `src/lib/env.ts` (`@t3-oss/env-nextjs`). Never scatter `process.env` reads in `src/`. Convex-side code reads its own `process.env` (separate runtime).
- **Zero-config boot**: the app must build and render useful setup states with NO optional keys set (AI, Polar, Resend, PostHog all gracefully optional). Never add a hard dependency on a paid key.

## Safety rules (non-negotiable)

1. **Confirm Gate**: any AI-driven mutation (Sigma tools that create/update/delete) MUST go through the server-enforced approval flow. Never let a tool write without a user-created approval record. Denial must leave zero trace.
2. **Ownership**: every Convex query/mutation verifies the record belongs to `ctx.userId` before reading/writing.
3. **Tool cap**: Sigma has at most 7 tools. Adding an 8th requires editing the plan doc first.
4. **Scope guardrails** (see plan §8): no RAG/uploads/embeddings, no teams/orgs, no admin panel, no notification center, no metered billing, no new auth providers, no i18n, no monorepo split.
5. **Rate limits**: AI endpoints enforce plan-based limits via `@convex-dev/rate-limiter`. Never bypass.

## Conventions

- TypeScript strict; functional patterns; named exports for components.
- Directories kebab-case. Files: component.tsx / hook in `src/hooks` / lib in `src/lib`.
- Zod schemas colocated with the module that owns the data.
- Copy existing patterns before inventing new ones: `convex/projects.ts` (auth'd CRUD), dashboard pages (loading/empty states), `emails/` templates.
- Comments only for constraints code can't express. No changelog comments.

## Extension recipes

### Swap the Noun (Runs → your entity)

The demo product is an AI run loop. To fork ChadNext for a different domain
(e.g. "imports", "invoices", "campaigns"), rename/rework the noun in these
files, in this order:

1. **Schema** — `convex/schema.ts`: rename the `runs` table + its indexes
   (`by_userId`, `by_userId_and_status`). Keep `userId` as the first index
   field: every query in the app filters by owner through it.
2. **Backend split** — `convex/runs.ts` is two layers. Public functions
   (`list`, `get`, `getStats`, `createRun`, `retryRun`, `deleteRun`,
   `processRun`) resolve the viewer via better-auth and delegate to
   `*Internal` functions that take an explicit `userId`. Keep this split:
   Sigma's tools and the scheduler call the internal layer directly. Port the
   status machine (`queued → running → succeeded/failed`), the metering fields
   (`tokensUsed`, `costCents`), and the daily-quota check
   (`internal.billing.getUserPlanInternal` + `convex/limits.ts`) to your
   domain or delete them if your entity is passive (no async processing).
3. **Quota + plan config** — `convex/limits.ts` (free daily limit) and
   `src/config/subscription.ts` (plan copy + limits shown in the UI). The
   billing page and upgrade prompts read from these; the Polar product id is
   env-only (`POLAR_PRO_PRODUCT_ID`).
4. **Dashboard UI** — `src/app/dashboard/runs/page.tsx` (TanStack Table via
   `convexQuery`) and `src/app/dashboard/runs/[runId]/page.tsx` (artifact
   viewer). Keep the loading / error / empty states; keep routing clicks off
   the table row if you remove them.
5. **Home stats** — `src/components/dashboard/run-stats-cards.tsx` +
   `convex/runs.ts getStats`.
6. **Sigma tools** — `convex/sigma.ts`: re-point the 7 tools'
   `ctx.runQuery/runMutation(internal.<module>.*)` calls at your new internal
   functions, and rename the gated tool names everywhere they appear as
   strings (`createRun`/`retryRun`/`deleteRun` in `gateApproval(...)`,
   `executeApprovedTool`, and the approval records' `toolName`).
7. **Generative UI** — `src/components/sigma/chat-message.tsx`
   (`ToolPartView` branches on tool name) and
   `src/components/dashboard/run-stats-cards.tsx`.
8. **Demo data** — `convex/seed.ts` (empty-state "Load demo data" button
   depends on `api.seed.seedDemoRuns`).

Run `pnpm build` after step 2 — the generated `api.ts` is stale until the
user runs `npx convex dev`; never hand-edit `convex/_generated/`.

### Add a Sigma tool

Sigma has **at most 7 tools** (safety rule 3). Replacing one is fine; adding
an 8th requires editing the plan doc first.

1. **Business logic first** — add an `internalQuery` (read) or
   `internalMutation` (write) in the Convex module that owns the data
   (e.g. `convex/runs.ts`). It must take an explicit `userId: v.id("users")`
   and verify ownership — tools pass `ctx.userId` through; they are the
   caller's identity, not a trust boundary by themselves.
2. **Define the tool** in `convex/sigma.ts` with `createTool`:
   - `description`: one sentence, action-oriented (the model picks tools from
     this).
   - `inputSchema`: zod object. Keep args primitive (ids as `z.string()`,
     cast to `GenericId<"…">` inside `execute`).
   - `execute: async (ctx, args, options)` — `ctx.userId` is set by the
     Agent component. Reads: `ctx.runQuery(internal.…, { userId: ctx.userId,
     … })` and return plain JSON (this becomes the model's tool result AND
     the generative-UI payload — shape it for both).
3. **Confirm Gate for writes** (non-negotiable, safety rule 1):
   - `needsApproval: gateApproval("yourToolName")` — persists a pending
     `approvals` record and pauses the model loop until the user decides.
   - Inside `execute`, call `assertApprovedToolCall(ctx, ctx.userId,
     ctx.threadId, options.toolCallId, "yourToolName")` BEFORE the mutation.
     It throws unless an approved, user-owned record exists — never skip it,
     never trust `needsApproval` alone.
   - Add a mock-mode branch in the `executeApprovedTool` internalAction so
     the gate still works with zero API keys.
4. **Register** the tool in the Agent constructor's `tools:` map
   (`listRuns`…`deleteRun` block) and mention it in `SIGMA_INSTRUCTIONS` if
   it changes what Sigma can do.
5. **Generative UI** — in `src/components/sigma/chat-message.tsx`
   `ToolPartView`, add a branch for your tool name that renders the output as
   a live component (see `RunsResultCard` / `StatsResultCard`). Unlisted tools
   fall back to the generic `ToolCard` — fine for most tools.
6. **Verify the gate**: attempt the write without approving; it must fail
   with the Confirm-Gate error and leave zero data side-effects.

## Design sourcing (keep the UI coherent)

- **Tier 1 (default)**: shadcn/ui core + official blocks + charts + official chat components (Message/Bubble/MessageScroller/Attachment/Marker).
- **Tier 2 (pieces)**: 21st.dev registry, Origin UI (primitives), Magic UI (landing motion), tweakcn (theme tokens).
- **Aesthetic**: dark techno-futurist (refs: Linear, Vercel, Resend). Bento grids for feature sections. Functional motion only — always respect `prefers-reduced-motion`.
- Never add heavy client-side animation libs for decoration.

## Before you commit

1. `pnpm build` green, `pnpm lint` clean.
2. No edits inside `convex/_generated/`.
3. New env vars: add to `src/lib/env.ts` + `example.env` with a comment (and note if optional).
4. Changes touching Sigma tools, billing, or auth: verify the relevant safety rule above still holds.
