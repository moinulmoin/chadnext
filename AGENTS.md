# ChadNext — Agent Guide

ChadNext is an **agent-native SaaS starter**: Next.js 16 + Convex + better-auth + Polar + AI SDK v7, whose demo product is an AI run-loop app with an in-app assistant ("Sigma"). This file is the single source of truth for AI coding agents (Claude Code, Cursor, Codex). Tool-specific files (`CLAUDE.md`, `.cursor/rules/`) point here — never edit them to diverge.

**The definitive plan** (scope, guardrails, phases): `docs/plans/2026-09-01-chadnext-v2-definitive-plan.md`. Read it before any feature work.

## Commands

```bash
pnpm dev          # dev server (Turbopack). Note: Serwist PWA is prod-only.
pnpm build        # production build — must pass before any commit
pnpm lint         # eslint
npx convex dev    # Convex backend — REQUIRES interactive login; ask the user to run it
```

## Stack invariants (violating these breaks the template)

- **Next.js 16**: `src/proxy.ts` (NOT middleware.ts). `params`/`searchParams`/`cookies()`/`headers()` are async — always `await`.
- **Tailwind 4**: CSS-first config in `src/app/globals.css`. No `tailwind.config.*` exists; never create one.
- **Convex is the only backend.** Data + business logic live in `convex/` with explicit validators and per-user ownership checks. Never add another database. Never call internal mutations without auth context.
- **Auth**: better-auth (GitHub OAuth + Email OTP) via `@convex-dev/better-auth`. All dashboard data is scoped by `ctx.userId`.
- **Billing**: Polar fixed tiers (Free/Pro) defined in `src/config/subscription.ts`. No usage-based/metered billing — ever.
- **AI**: AI SDK v7. Provider resolution: `src/config/ai.ts` (Next-side) and `convex/aiConfig.ts` (Convex-side), priority = Vercel AI Gateway → OpenAI → Anthropic → mock. `@convex-dev/agent` v0.7+ uses `instructions:` (not `system:`).
- **Client data layer**: TanStack Query via `@convex-dev/react-query` — use `convexQuery(api.x.y, args)` with `useQuery` from `@tanstack/react-query`. Native `convex/react` `useQuery` is allowed for quick internals but prefer the adapter for new pages.
- **Env**: all Next-side env access goes through `src/lib/env.ts` (`@t3-oss/env-nextjs`). Never scatter `process.env` reads in `src/`. Convex-side code reads its own `process.env` (separate runtime).
- **Zero-config boot**: the app must build and render useful setup states with NO optional keys set (AI, Polar, Resend, PostHog all gracefully optional). Never add a hard dependency on a paid key.

## Safety rules (non-negotiable)

1. **Confirm Gate**: any AI-driven mutation (Sigma tools that create/update/delete) MUST go through the server-enforced approval flow. Never let a tool write without a user-created approval record. Denial must leave zero trace.
2. **Ownership**: every Convex query/mutation verifies the record belongs to `ctx.userId` before reading/writing.
3. **Tool cap**: Sigma has at most 7 tools. Adding an 8th requires editing the plan doc first.
4. **Scope guardrails** (see plan §8): no RAG/uploads/embeddings, no teams/orgs, no admin panel, no notification center, no metered billing, no new auth providers, no i18n, no monorepo split.
5. **Rate limits**: AI endpoints enforce plan-based limits via `@convex-dev/rate-limiter`. Never bypass.

## Conventions

- TypeScript strict; functional patterns; named exports for components.
- Directories kebab-case. Files: component.tsx / hook in `src/hooks` / lib in `src/lib`.
- Zod schemas colocated with the module that owns the data.
- Copy existing patterns before inventing new ones: `convex/projects.ts` (auth'd CRUD), dashboard pages (loading/empty states), `emails/` templates.
- Comments only for constraints code can't express. No changelog comments.

### Add a Sigma tool
*(completed in P5 — placeholder)* Define business logic as a Convex function → wrap with `createTool` scoped to `ctx.userId` → reads auto-run, mutations behind the Confirm Gate → add UI rendering + docs.

## Design sourcing (keep the UI coherent)

- **Tier 1 (default)**: shadcn/ui core + official blocks + charts + official chat components (Message/Bubble/MessageScroller/Attachment/Marker).
- **Tier 2 (pieces)**: 21st.dev registry, Origin UI (primitives), Magic UI (landing motion), tweakcn (theme tokens).
- **Aesthetic**: dark techno-futurist (refs: Linear, Vercel, Resend). Bento grids for feature sections. Functional motion only — always respect `prefers-reduced-motion`.
- Never add heavy client-side animation libs for decoration.

## Before you commit

1. `pnpm build` green, `pnpm lint` clean.
2. No edits inside `convex/_generated/`.
3. New env vars: add to `src/lib/env.ts` + `example.env` with a comment (and note if optional).
4. Changes touching Sigma tools, billing, or auth: verify the relevant safety rule above still holds.
